🔍 Key Design Notes

  • Like uses composite primary key (userId, postId) to prevent duplicate likes
  • Follow is a self-referencing many-to-many relationship for user connections
  • AuthorProfile has a one-to-one relationship with User via unique userId
  • PostView.userId is nullable to track anonymous views via ipHash
  • Post.content stores JSONB for flexible block-based content (markdown, plaintext, images)
  • RefreshToken.tokenHash is hashed for security with both unique constraint and index
  • Cascade delete on all foreign keys except Comment.userId (RESTRICT) and PostView.userId (SET NULL)
